# v0.1 — CRAP + Mutation Testing 五階段流水線示範工具（初版）

## 版本目標與範圍

從 0 到 1 做出可實際執行的五階段流水線示範工具（Specification → Writing → Cleanup(CRAP) →
Strengthening(Mutation) → QA），對應 `plan.md` 全部 8 個子任務。這是第一個版本，範圍涵蓋：

- 通用 CRAP Score 計算（跨 5 語言共用複雜度計數器）
- 通用 Mutation Testing engine（正規表示式文字替換）
- 5 語言（Python/Go/Rust/JavaScript/C）的原生 coverage 工具整合
- Stage 1/2 真的呼叫 `claude -p` headless CLI 產生驗收測試與程式碼
- 完整 orchestration（含 CRAP/Mutation 不合格時打回 Stage 2 重寫，max_retries=3）

## 變更項目

### 新增
- `pipeline/crap.py`：CRAP 公式 + 五語言通用環形複雜度計數器
- `pipeline/mutation.py`：通用 mutation engine（>=、<=、==、!=、&&、||、and/or、true/false、+、-、>、< 共 12 種算子）
- `pipeline/languages/*`：五語言的 coverage 指令與原生工具輸出 parser
- `pipeline/claude_agent.py`：呼叫 `claude -p` 的 wrapper + Stage1/Stage2 prompt 產生器 + 多檔案回覆解析
- `pipeline/state.py`：任務狀態存檔/讀取（JSON）
- `pipeline/cli.py`：`run` 子指令，串起完整五階段 orchestration（目前只接 Python）
- `examples/{python,go,rust,javascript,c}`：五語言各一個示範函式 + 測試
- 22 個單元測試（`tests/unit/`）+ 7 個系統測試（`tests/system/`，會真的呼叫 coverage.py / go test / cargo-tarpaulin / c8 / gcc+gcov）

### 修正（過程中發現的問題）
- 原文章表格 comp=10/cov=80% 寫 10.1，套公式實算為 10.8，判斷為原文筆誤，測試以公式結果為準
- Mutation engine 對字串常數內剛好含有 `-` 的內容（如錯誤訊息 "non-negative"）會誤判為可變異運算子；
  已知限制（純文字替換，不解析語法樹），示範範例改用不含運算子符號的錯誤訊息文字迴避

### 架構決策記錄
- **未產出** `templates/prompt_template.md` 獨立檔案：Stage1/2 的 prompt 內容直接寫在
  `pipeline/claude_agent.py` 的 `build_stage1_prompt`/`build_stage2_prompt` 函式裡，
  避免同一份 prompt 邏輯要維護兩份（.md 範本 + 程式碼），屬於對 plan.md 目錄結構的簡化偏離

## 風險 / 相容性 / 回滾

- **風險**：Mutation engine 是正規表示式文字替換，對複雜語法（巢狀泛型、字串常數含運算子符號）可能誤判，
  非工業級精度，僅供示範五階段流程用（已於 plan.md 與本文件記錄）
- **風險**：Stage1/2 呼叫真實 `claude -p` 會消耗使用者帳號 token，且輸出非決定性（同樣需求每次產出程式碼可能不同）
- **相容性**：目前 `pipeline/cli.py run` 的 orchestration 只接 Python；Go/Rust/JS/C 的 Cleanup+Strengthening
  building block（coverage/CRAP/mutation）已個別驗證可用，但尚未接上 Stage1/2/orchestration 迴圈
- **回滾**：本專案為獨立示範工具，未修改 repo 其他任何既有檔案，若要移除整個功能，直接刪除
  `crap-mutation-pipeline-demo/` 目錄即可，無殘留副作用
