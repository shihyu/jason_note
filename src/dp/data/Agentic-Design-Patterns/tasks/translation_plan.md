# Agentic Design Patterns 中文翻譯計畫

* * *

## 一、目標與原則

1. 以「可讀、可維護、可復用」為核心，先完成書籍核心章節再擴展到附錄。
2. 確保翻譯品質一致：關鍵術語固定、專有名詞保留英文、句意先準確再追求修飾。
3. 保留技術內容與程式碼結構，不動 Markdown 連結與程式區塊語法。
4. 圖片 (`png`) 不主動改檔名，不改原始位址；只翻譯 Markdown 的替代文字或必要說明文字。
5. 本案採直接取代策略（overwrite）：同名文件直接覆蓋成 zh-tw 版本，工作目錄不保留原文副本。
6. 唯一保留原文的方式是 Git 歷史，不在工作目錄維持雙語並存檔案。

## 四、覆蓋規則（實作重點）

- 每個目標 `.md` 檔，翻譯完成後直接覆蓋原檔。
- 不建立 `*-zh-tw.md`、`*_cn.md` 或任何複本檔名。
- 不建立原文留存資料夾（如 `original/`、`en/`）。
- 需要回溯時，由 `git log` / `git show` 查版本紀錄，非保留於工作目錄。

## 六、每檔案執行規格

### 基本規則
- 章節標題、術語、重點段落先寫完整、後修辭。
- 保留原文中的：
  - 程式碼區塊
  - 命令列與網址
  - API 呼叫與參數名稱
- Markdown 連結文字與目標檔案路徑保持一致，禁止改掉原有路徑。
- 內容完整改為 zh-tw，可保留必要的英文專有名詞、指令與專有縮寫，不建立英文替代檔。
- 每個檔案完成後立即覆蓋原始檔，並確認 `git diff` 僅為同名檔內容替換。

### 品質檢核
- 語意完整性：段落主詞、邏輯關係、轉折詞正確。
- 術語一致性：新用到名詞必需回填到術語表。
- 章節首尾完整：不省略段首摘要與段尾結語。
- 覆蓋一致性：未產生重複文件、未留下英文對照文件、未新增不必要副檔。
- 驗證項目：
  - 兩人以上逐段抽查 1/3 內容
  - 一輪全文快速回讀確認連續性
  - 一輪 Markdown 語法掃描（連結、標題、表格）

新增「信達雅」檢核（每篇至少通過以下 3 輪）：
- 第一輪（信）：逐段對照英文原文，確認術語對應、關係邏輯、條件與因果是否保留。
- 第二輪（達）：用「閱讀通順度」清單逐句檢查，重點確認斷句、代詞與轉折連接是否清晰，並調整不自然句型。
- 第三輪（雅）：全篇語感整飭，統一台灣用語（例如：範例、示範、品質、文件）與行文風格，刪除機器式直譯痕跡，保留技術敘述的精準與簡潔。
- 每輪結束後於 `tasks/review_log.md` 紀錄：
  - 發現項目編號（章節+段號）
  - 回溯修正項目
  - 是否通過（是/否）

## 八、輸出格式與版本控制建議

1. 每完成一個階段，先交付 `tasks/` 內的進度摘要，待核可後再提交對應章節檔案。
2. 單檔更新建議限制在 5~10 篇章節內，便於版本回溯。
3. 提交資訊請依 Conventional Commits 1.0.0，摘要採現在式、中文動詞式，例如：
   - `feat(translate): 覆蓋第一部分章節為中文翻譯`
4. 每個階段結束前先確認：
   - `git status --short` 中無非目標檔案異動
   - 無 `.bak`、`.orig`、`.tmp`、`.swp` 等備援檔

## 九、Subagent 協作策略（優先）
- 盡量使用 subagents，優先採平行分工並保留單一主責整合者。
- 角色建議：
  - 翻譯 subagent：產出第一版中文草稿，保留英文專有名詞與指令參數。
  - 語意 subagent：逐段比對原文，回報主詞、邏輯、條件與因果偏差。
  - 詞彙語感 subagent：修正台灣語句節奏、代詞、銜接詞與專有詞一致性。
  - 術語 subagent：同步更新與回填 `terms_zh-tw.md`，檢查跨篇名詞一致。
- 實作流程：
  - 第 1 輪：翻譯 subagent 先行提交 draft。
  - 第 2 輪：語意與詞彙語感 subagent 依草稿回報修正清單。
  - 第 3 輪：主責整合者彙整後一次覆蓋目標 `.md` 檔。
  - 第 4 輪：術語 subagent 核對並更新術語表，必要時回註修正。
- 紀錄要求：每一輪修正要在 `tasks/review_log.md` 紀錄負責 subagent、問題類型、採納結論與修改結果。
- 無法動用 subagent 時，主責者需逐段走信達雅三輪檢核，並補齊同等紀錄。
